# 고객과 문제

새 프로젝트는 이 파일을 자기 프로젝트 루트의 customer.md로 복사합니다. 기존 파일이 있으면 먼저 읽고 필요한 절을 병합합니다. [괄호]는 자기 자료로 바꾸고 모르면 미확인, 확인 담당과 날짜를 적습니다. 실제 고객 자료의 접근과 보관은 프로젝트의 허용 범위를 따릅니다.

## 결정 연결

- 관련 결정: [progress.md의 DEC-ID와 질문 한 문장]
- 관련 목표: [prd.md의 목표 절]
- 작성일: [YYYY-MM-DD]

## 역할과 문제

| 역할 | 하는 일과 겪는 상황 | 기대 결과 | 확인 상태 |
|---|---|---|---|
| 사용자 | [실제로 사용할 사람의 역할과 최근 장면] | [기능 이름 없이 바뀌길 바라는 결과] | [자료 ID 또는 미확인] |
| 구매자 | [비용, 도입을 결정하는 역할, 해당 없으면 이유] | [예산, 도입, 위험에 관한 기대] | [자료 ID 또는 미확인] |
| 운영자 | [오류와 문의, 복구를 맡는 역할] | [감당 가능한 운영 결과] | [자료 ID 또는 미확인] |

문제 가설: [누가, 어떤 상황에서, 현재 방법으로 무엇을 하다가, 어떤 결과를 얻지 못하는지 한 문장. 실제 확인 전에는 가설 표기]

## 최근 사건과 자료

| 자료 ID | 종류와 출처, 날짜 | 읽거나 관찰한 내용 | 해석과 한계 |
|---|---|---|---|
| [INPUT-01 등] | [업무 입력, 실제 인터뷰, 동료 검토 등을 구별. 원문 위치와 확인일] | [자료에 실제로 있는 말이나 행동] | [작성자의 가설과 미확인. 연습 입력은 고객 증거로 세지 않음] |

실제 인터뷰, 관찰이 없으면 그 사실을 적습니다. AI 설명과 페르소나 응답은 고객 발언으로 옮기지 않습니다. 공개할 자료에는 개인 식별 정보와 비공개 링크를 넣지 않습니다.

## 현재 대안

| 대안 | 지금 끝낼 수 있는 일 | 불편과 전환 부담 | 출처와 미확인 |
|---|---|---|---|
| [수작업] | [현재 처리 결과] | [남는 불편, 새 도구로 옮길 때 부담] | [자료 ID 또는 확인 계획] |
| [기존 도구나 경쟁 제품] | [확인한 기능과 확인일] | [실제로 관찰한 제약, 모르면 미확인] | [공식 자료 또는 직접 확인 위치] |
| [그대로 두기] | [변경하지 않아 지킬 수 있는 것] | [그대로 둘 때 손실] | [자료 ID 또는 가설] |

## 가정과 반대 근거

- 가장 약한 가정: [틀리면 이번 선택이 바뀌는 문장]
- 지지 자료: [자료 ID와 정확히 지지하는 부분, 없으면 미확인]
- 반대 자료: [자료 ID와 선택을 바꿀 내용, 없으면 찾지 못함과 확인 방법]
- 다음 확인: [실제 최근 행동을 묻는 질문 하나 또는 관찰 행동]
- 확인 담당과 날짜: [역할, YYYY-MM-DD]

여기의 고객 기대가 품질 기준의 이유가 됩니다. 확정한 기준은 prd.md에만 두고 해당 Q-ID를 참조합니다. 실제 선택과 7일 리뷰는 progress.md에 덧붙입니다.
