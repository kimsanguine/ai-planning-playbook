# 사례 B, 품질과 비용의 손실을 함께 고르기

## Q. 실제 논의에서 어떤 충돌이 있었나요?

영상 AI의 길이 보정에 반복 작업이 들어가면서 비용이 커질 수 있다는 우려가 있었습니다. 반복 횟수 축소, 자원 할당 변경, 대체 모델 검토가 제안됐어요. 저는 반복을 줄이면 번역 품질에 어떤 영향이 생기는지, 평균 재시도와 언어별 차이는 어떤지, 반복마다 의미 있는 개선이 있는지 물었습니다. 자원 할당을 줄일 때 대기 경험에 미칠 영향도 함께 볼 문제였습니다.

당시 유료 전환을 위해 무료 사용자의 다운로드를 제한하는 안도 검토했습니다. 저는 다운로드를 막아도 생성은 여전히 가능하므로 비용에는 큰 영향이 없다고 봤습니다. 생성에서 비용이 생기는데 내려받는 마지막 행동만 제한하면 원가를 만드는 흐름은 남기 때문입니다. 전환을 유도하는 장치와 생성 비용을 줄이는 장치는 같은 역할이 아니었습니다.

제가 먼저 묻는 질문은 “지금 비용을 만드는 행동은 무엇인가?”입니다. 그다음 반복을 줄여 잃을 품질과 자원을 줄여 늘어날 수 있는 대기를 봅니다. 빨리 제한할수록 확인 시간이 줄어드는 갈등도 있습니다. 여러분도 생성, 재시도, 다운로드의 단위를 나누고 어느 행동을 바꿀지 고르세요. progress.md의 현재 DEC-ID 아래 검토 메모에 비용을 만드는 행동과 그대로 둘 행동을 적고, 선택과 이유에 감내할 손실을 남깁니다. 실제 처리 구조가 다르면 같은 결론을 가져오지 않습니다.

## Q. 어떤 조건이면 다른 선택이 먼저인가요?

긴급한 장애나 감당할 수 없는 지출이 이미 확인됐다면 임시 제한이 먼저일 수 있어요. 다만 누가 허용하고 언제 복구할지 정합니다. 반대로 품질을 잘못 낮추면 돌이킬 손실이 큰 작업은 생성 보류나 수동 처리가 먼저일 수 있습니다. 비용을 줄인다는 이유로 기존 약속을 조용히 바꾸지 않습니다.

## 독립 실습 B, 선택 구간의 재시도안

이하 입력은 과거 내부 기록과 별개의 연습 자료입니다. 다른 사례나 핸드북 전체를 읽지 않아도 진행할 수 있습니다. [../templates/customer.md](../templates/customer.md)에서 네 파일을 자기 프로젝트에 준비합니다. 채운 연결은 [../examples/video-localization/customer.md](../examples/video-localization/customer.md)부터 볼 수 있습니다. 이미 실제 결과가 있는 프로젝트에는 필요한 절만 병합합니다.

INPUT-01: 번역과 더빙을 마친 영상의 한 구간에서 길이가 맞지 않습니다. 전체 영상 재생성 대신 작업자가 시작과 끝을 선택한 한 구간의 재시도안을 검토합니다. 원본 보존, 선택 구간 밖 변경 금지, 자동 게시 없음. 단가, 비용 한도, 재시도 상한 수치, 실제 고객 지불 의향과 자료 전송 권한은 미확인입니다. 한도와 권한이 정해지기 전 실제 생성은 보류하며 문서와 수동 검토는 가능합니다.

## Q. 어떤 요청으로 비교를 시작하나요?

입력 양식: 문제 [수정 장면], 대안 [비교할 방법], 품질 [지킬 것], 미확인 [비용과 권한]. 먼저 이 본문을 붙입니다.

```text
위 대안에서 [검토할 안]을 고르기 전에 확인할 품질과 비용의 충돌 하나를 설명해줘. 없는 수치와 고객 근거는 만들지 마.
```

채운 실행예: INPUT-01과 “수동 편집, 전체 재생성, 선택 구간 검토, 기존 결과 유지”를 먼저 붙입니다.

```text
위 대안에서 선택 구간 재시도안을 고르기 전에 확인할 품질과 비용의 충돌 하나를 설명해줘. 없는 수치와 고객 근거는 만들지 마.
```

설명용 응답예: “반복을 줄이면 비용이 줄 수 있지만 길이와 의미가 맞는 후보를 얻지 못할 수 있어 실제 결과와 처리량이 필요하다.” 실제 시험 결과가 아닙니다. 한 구간이라 반드시 싸다는 응답은 채택하지 않습니다. AI 없이도 대안별 얻는 것, 감수할 것, 필요한 자료를 손으로 비교할 수 있어요.

## Q. 사람은 어디까지 허용하고 무엇을 남기나요?

수동 검토 진행, 추가 자료 확인, 현재 상태 유지 중 지금 할 행동을 고릅니다. 설명예의 선택은 구간 선택과 후보 채택 절차를 수동으로 검토하고 실제 생성과 전체 개발은 보류하는 것입니다. 모르는 단가와 상한을 임의로 정해 생성하지 않습니다. 자료가 부족하면 확인 담당과 날짜를 남기고 수동 대안을 유지하세요.

| 파일 | 이번에 저장할 내용 |
|---|---|
| customer.md | INPUT-01의 연습 성격, 문제 가설, 수동 편집 등 현재 대안, 실제 인터뷰 없음 |
| prd.md | Q1 원본 보존, Q2 선택 구간만 변경, Q3 단가, 재시도 상한, 승인 확인 전 생성 보류. 비용 한도도 확인 대상 |
| architecture.md | 범위와 권한은 규칙, 후보는 모델, 채택은 사람. 원본 분리, 실패 시 중단과 수동 복구, 코드 미구현 |
| progress.md | DEC-B01 또는 자기 DEC-ID, 대안과 감수한 것, 허용과 보류, owner, 7일 뒤 review, actual 빈칸 |

네 파일을 저장하고 다시 열어 Q1부터 Q3까지가 서로 같은지 읽습니다. 실제로 수동 검토했다면 새 항목에 관찰을 적습니다. 7일 뒤에는 유지, 수정, 축소, 중단/보류, 추가 관찰 중 고릅니다. 한도와 권한이 없으면 생성 보류를 유지하고, 수동 대안이 충분한 실제 근거가 생기면 범위 축소를 검토합니다. 추가 관찰을 고르면 확인 대상, 담당, 날짜와 그동안 보류할 실행 범위를 함께 적습니다. 계획과 실제 결과를 같은 칸에 쓰지 않습니다.

## 조건이 달라진 추가 연습

### Q. 보류한 뒤 새 조건이 생기면 선택을 어떻게 바꾸나요?

아래는 조건 변경 연습입니다. 새 고객 관찰이나 모델 시험의 실제 결과가 아닙니다. 채운 네 예시 파일을 별도 연습 폴더에 복사해 DEC-001에서 시작하세요. 자기 실제 프로젝트의 결정과 미래 actual은 그대로 둡니다. 연습본에서도 actual은 비우고, 가정 관찰은 별도 항목에 적습니다. 모델 호출과 실제 생성을 하지 않고 같은 네 문서의 변경을 연습합니다.

INPUT-02, 가정 관찰: 수동으로 선택 구간을 따라가는 장면에서 두 검토자가 시작과 끝을 서로 다르게 읽었다고 가정합니다. Q2의 “선택 구간만 변경”은 유지하지만, 현재 확인법으로 두 사람이 같은 범위를 보는지 분명하지 않습니다. 아래 조건 카드 하나를 골라 이 가정에 더합니다.

| 조건 카드 | 새로 주어진 연습 조건 | 비교할 선택 |
|---|---|---|
| A, 수동 대안이 충분함 | 수동 편집만으로 목표를 끝낼 수 있었다고 가정합니다. 추가 생성의 필요는 확인되지 않았습니다. | 생성 검토 범위를 축소해 수동 수정과 범위 확인에 집중할지, 무엇을 더 관찰할지 |
| B, 좁은 시험 조건을 정할 수 있음 | 해당 시험의 자료 권한과 승인자, 단가, 비용 한도와 재시도 상한, 결과의 범위 확인법이 승인 문서에서 확인됐다고 가정합니다. 값이나 승인이 실제로 생긴 것은 아닙니다. | 전체 개발을 계속 보류하면서 승인된 한 구간의 제한된 시험을 검토할지, 먼저 범위 확인 절차를 고칠지 |

A와 B의 선택이 왜 달라지는지 한 문장씩 비교하고 하나를 골라 작성합니다. B에서도 실제 비용과 품질, 수요의 결과는 없습니다. 좁은 시험의 입력과 종료, 복구를 검토할 근거가 생긴 것이며 전체 개발의 근거로 넓히지 않습니다. 숫자와 실제 승인 문서를 만들어 생성하지 마세요. 두 카드에서 확신할 수 없다면 중단/보류나 추가 관찰도 선택할 수 있습니다.

### Q. REVIEW-001에서 DEC-002까지 무엇을 직접 쓰나요?

연습본의 progress.md에 다음 순서로 새 항목을 덧붙입니다. 기존 DEC-001의 질문, 이유와 actual은 고치지 않습니다. 아래 표의 내용은 작성 지시이며 실제 관찰 기록이 아닙니다.

| 위치 | 직접 작성할 내용 |
|---|---|
| customer.md의 최근 사건과 자료 | INPUT-02, 종류 “조건 변경 연습의 가정 관찰”, 고른 A/B와 실제 고객 근거 아님을 적습니다. |
| progress.md의 7일 리뷰 REVIEW-001 | reviews는 DEC-001, 기록 종류는 조건 변경 연습. “연습에서 주어진 관찰” 항목에 INPUT-02와 카드 조건을 요약하고 actual은 비웁니다. |
| REVIEW-001의 다음 선택 | 유지, 수정, 축소, 중단/보류, 추가 관찰 중 하나와 이유를 씁니다. 추가 관찰이면 확인 대상, 담당, 날짜와 그동안 보류할 범위를 모두 정합니다. |
| progress.md의 새 결정 DEC-002 | DEC-001과 REVIEW-001 참조, 고른 카드, 버린 대안과 이유, 이번 허용과 보류, owner와 review를 적습니다. actual은 비웁니다. |

카드 A라면 생성 검토를 축소하고 수동 수정에서 구간 확인을 남길 이유를, B라면 좁은 시험 전 어떤 범위를 사람이 확정해야 하는지 적어 보세요. 선택지가 수정이라면 바꿀 절차와 현재 허용을 구체적으로 씁니다. 기준 변경을 확정한 뒤에만 아래 문서를 갱신합니다.

### Q. 정본과 처리에서는 무엇을 바꾸고 무엇을 지키나요?

prd.md의 Q2 조건 “선택 구간만 변경”은 유지합니다. 확인 방법에는 작업자가 시작과 끝을 같은 시간 기준으로 표시하고, 검토자가 표시된 범위를 다시 확인하며, 후보가 있으면 구간 밖 원본과 대조하는 절차를 구체화하세요. 수동 검토에서는 후보 비교를 했다고 쓰지 않습니다. Q1 원본 보존과 Q3의 실행 전 확인을 삭제하거나 완화하지 않습니다. Q2의 확인법 변경 이유는 DEC-002를 참조합니다.

architecture.md의 처리 1번과 2번에는 시작과 끝의 표시, 사람의 범위 재확인, 모호하면 중단하고 재선택하는 처리를 연결합니다. 카드 A에서는 수동 수정까지만 허용하고, 카드 B에서도 좁은 시험의 승인 범위를 넘지 않도록 씁니다. 모델이 범위나 한도를 추측하게 하지 않습니다. 실제 코드가 생겼다고 상태를 바꾸지 않습니다.

마지막으로 네 파일을 저장하고 다시 엽니다. INPUT-02가 실제 관찰로 승격되지 않았는지, REVIEW-001이 DEC-001을 가리키는지, DEC-002 뒤 Q2 확인법과 처리의 범위 확인이 함께 바뀌었는지 읽습니다. progress.md의 재사용 기준에는 “비용을 만드는 행동과 제한하는 행동을 나눠 본다” 같은 기준을 근거 DEC-ID와 연결하고, 이 기준을 그대로 쓸 조건과 바꿀 조건을 자기 말로 적으세요.
