# 사례 A, 기능 요청에서 문제로 돌아가기

## Q. 실제로 어떤 상황에서 판단을 바꿨나요?

구인구직 서비스를 맡았을 때, 출근 전 노쇼에 페널티를 주고 그런 사람을 표시해 달라는 요구가 있었습니다. 저는 고객 문제를 다시 정의하는 프레임을 제안했고, 양쪽 모두 책임을 갖도록 전자계약 절차를 도입했습니다. 출근 일정을 잡으면 계약서를 작성하는 흐름을 추가한 경험입니다.

여기서 갈등은 고객의 명확한 요청을 따르는 것과 요청 밖의 해결책을 찾는 것 사이에 있습니다. 요청이 페널티라는 기능 이름으로 고정되면 그 기능의 설계만 논의하게 돼요. 저는 기능을 지운 뒤에도 고객이 이루려는 결과를 설명할 수 있는지 봅니다. 출근 전 약속과 양쪽의 책임을 다루는 방향을 택한 이유가 여기에 있습니다. 여러분의 과제에서는 절차를 추가한 뒤 약속을 지키는 행동과 중도 이탈이 어떻게 달라지는지 함께 보세요. 문제를 재정의한 선택과 실제 효과를 확인하는 일은 이어져야 합니다.

## Q. 다른 조건에서도 계약 절차를 고르면 되나요?

그렇지 않습니다. 책임 범위가 이미 분명한데 고의적 악용이 반복되거나, 즉시 피해를 막을 조치가 필요하다면 다른 접근이 먼저일 수 있어요. 계약 절차의 부담이 더 클 수도 있습니다. 고객이 요청한 기능을 부정하는 것이 목적이 아닙니다. 최근 사건, 현재 대처와 기대 결과, 다른 당사자의 부담을 확인한 뒤 고르는 것이 목적입니다.

## 독립 실습 A, 예약 업무 입력

이하 입력은 과거 구인구직 기록과 별개의 연습 자료입니다. 다른 사례를 읽지 않아도 진행할 수 있습니다. 자기 과제가 있으면 이 입력 대신 자신의 허용된 메모를 사용합니다. 먼저 [../templates/](../templates/customer.md)의 네 파일을 자기 프로젝트에 복사하거나 기존 파일에 필요한 절을 병합하세요.

INPUT-A01: 예약 담당자가 “노쇼한 사람을 표시하는 기능을 만들자”고 요청했습니다. 마지막 노쇼 사건의 날짜와 상황, 현재 대처, 발생 빈도와 원인은 아직 확인하지 않았습니다. 불이익을 줄 권한도 미확인입니다. 이번에는 요청을 문제 가설로 나누고 실제 사건을 확인할 질문을 정합니다. 사람에게 불이익을 주는 기능 적용은 허용하지 않습니다.

## Q. AI에게 무엇을 보내고 무엇을 읽나요?

입력 양식: 요청 [기능 문장], 최근 사건 [본문 또는 미확인], 현재 대처 [방법 또는 미확인], 허용 범위 [이번 행동]. 먼저 이 본문을 붙입니다.

```text
위 [요청]을 기능 이름이 없는 고객 문제 가설 한 문장으로 바꿔줘. 확인되지 않은 원인과 효과는 넣지 마.
```

채운 실행예: 위 INPUT-A01 전체를 먼저 붙입니다.

```text
위 노쇼 표시 요청을 기능 이름이 없는 고객 문제 가설 한 문장으로 바꿔줘. 확인되지 않은 원인과 효과는 넣지 마.
```

설명용 응답예: “예약 담당자가 예약 이행 여부를 미리 알기 어려워 준비에 차질을 겪을 수 있다.” 실제 모델 실행 결과가 아니며 이 문장도 확인 전에는 가설입니다. “노쇼가 빈번해 매출이 줄었다”처럼 없는 사건과 성과가 붙으면 그 부분을 버리고 직접 고치세요. AI 없이도 기능 이름을 지운 문제 문장을 직접 써 같은 선택을 할 수 있습니다.

## Q. 사람은 무엇을 선택하고 어디에 저장하나요?

즉시 기능 명세, 절차 재검토, 최근 사건 확인 가운데 하나를 고릅니다. 이 입력에서는 사건과 불이익 권한이 미확인이므로 “최근 사건을 먼저 묻고 기능 적용은 보류”를 선택하는 설명예를 볼 수 있습니다. 독자는 자기 조건에서 다른 선택을 해도 되며 근거와 책임을 적습니다. 후속 질문은 “마지막으로 예약이 이행되지 않았을 때 어떤 순서로 처리했나요?”처럼 실제 행동을 묻습니다.

| 파일 | 이번에 저장할 내용 |
|---|---|
| customer.md | INPUT-A01, 요청 원문과 문제 가설의 구분, 최근 사건과 현재 대안의 미확인, 다음 질문 |
| prd.md | 이번 목표는 사건 확인과 문제 재정의, 불이익 기능 적용 제외, 가설을 사실로 쓰지 않는 기준 |
| architecture.md | 담당자가 질문하고 답의 출처를 보관, 사람이 문제를 확정, 권한 전 적용 보류와 기존 절차 유지 |
| progress.md | DEC-A01, 선택지와 선택 이유, 포기한 것, owner, 시작일과 7일 뒤 review, actual 빈칸 |

자료를 구할 수 없으면 접근할 담당과 날짜를 정하고 보류 범위를 저장합니다. 이는 사건 확인을 마쳤다는 뜻이 아닙니다. 네 파일을 저장하고 다시 열어 요청이 PRD 기능으로 자동 확정되지 않았는지 확인하세요. 7일 뒤에는 실제 질문 여부와 받은 답을 새 리뷰에 적고 유지, 수정, 축소, 중단/보류, 추가 관찰 가운데 다음 선택을 남깁니다. 추가 관찰이면 확인 대상, 담당, 날짜와 그동안 보류할 실행 범위도 적습니다.
