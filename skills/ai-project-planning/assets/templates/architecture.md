# 처리 구조와 책임

기존 architecture.md에 필요한 절을 병합합니다. 제품 기준은 prd.md가 정본이며 이 파일은 처리, 코드 책임, 사람 검토와 복구를 설명합니다. 아직 구현하지 않은 흐름은 계획으로 적습니다.

## 입력과 출력

- 결정과 기준: [progress.md의 DEC-ID, prd.md의 Q-ID]
- 입력: [자료 종류, 자료 ID, 사용 권한과 허용 범위]
- 출력: [사용자가 받을 후보, 안내, 저장물과 형식]
- 구현 상태: [계획만 있음, 구현 중, 실제 확인한 것 등을 자신의 현재 사실로 기록]

## 처리와 HITL

| 순서 | 처리와 담당 | 기준 참조 | 사람이 확정할 일 |
|---|---|---|---|
| 1 | [사용자의 시작 입력] | [prd.md의 Q-ID] | [입력 권한과 범위 확인 역할] |
| 2 | [코드 규칙으로 판단할 조건] | [Q-ID] | [예외 승인 필요 여부] |
| 3 | [AI가 초안이나 후보를 만들 일, 없으면 해당 없음과 이유] | [Q-ID] | [실제 호출 전 한도, 전송 허용 역할] |
| 4 | [후보 대조와 전달] | [Q-ID] | [채택, 반려, 보류를 고를 역할] |

사람 검토는 HITL이며 순서 중 필요한 지점에 둡니다. 도구의 가능 여부와 실행 권한을 구분합니다. 재시도, 상태 코드와 한도 같은 명확한 조건은 코드 규칙으로 처리하고 모델이 추론하게 하지 않습니다.

## 개발 폴더 책임 예

프로젝트 문서: docs/customer.md, docs/prd.md, docs/architecture.md, docs/design.md, docs/progress.md.

| 폴더 | 책임 | 이번 과제의 내용 |
|---|---|---|
| src/domain/ | 범위, 권한, 한도 등의 결정적 규칙 | [담당 규칙 또는 계획] |
| src/adapters/ | 모델과 외부 시스템 연결 | [허용된 연결 또는 보류 이유] |
| tests/fixtures/ | 허용된 시험 입력 | [실제 사용할 입력, 비공개 원문 제외] |

이 표는 폴더 설계입니다. 실제로 만들지 않았다면 존재하거나 구현됐다고 쓰지 않습니다. 기존 코드 구조가 다르면 책임이 있는 실제 경로를 적습니다.

## 오류와 복구

| 실패 상황 | 즉시 행동과 안내 | 복구와 책임자 |
|---|---|---|
| [자료나 권한 부족] | [보류할 처리와 사용자가 받을 안내] | [확인 담당과 재개 조건] |
| [품질 기준 위반] | [원본, 기존 상태를 지킬 방법] | [되돌릴 대상과 담당] |
| [비용이나 재시도 상한 도달] | [추가 실행 중단과 남길 기록] | [사람 재승인 또는 수동 경로] |
