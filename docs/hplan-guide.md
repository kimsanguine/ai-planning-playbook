# 판단을 hplan으로 이어 쓰기

## Q. 네 문서로 끝낸 뒤 어떤 이유가 있을 때 도구로 옮기나요?

저는 같은 방향을 다시 논의할 때 과거의 제외 이유, 근거와 실제 결과를 꺼내야 하는지 봅니다. hplan은 근거와 비용, 이전 제외 이력의 확인, 결정 누적과 경험칙 재사용을 다루는 공개 프로젝트입니다. 한 번의 결정이라면 네 문서와 7일 리뷰로 충분할 수 있어요. 설치가 지금의 판단보다 더 큰 일이 된다면 기록을 먼저 유지합니다.

공식 출발점은 [hplan 저장소](https://github.com/kimsanguine/hplan)와 [한국어 README](https://github.com/kimsanguine/hplan/blob/main/README-ko.md)입니다. 실제 연결을 선택할 때 현재 지원 환경, 설정과 입력 형식을 여기서 확인하세요. 이 키트에서는 설치나 모델 호출 없이 준비할 판단과 자료를 정리합니다.

## Q. 어떤 내용을 입력으로 준비하나요?

자기 customer.md에서 실제 자료와 가설, 현재 대안을 고릅니다. prd.md에서는 목표와 품질 기준, 포함과 제외, 비용의 확인값과 빈칸을 고릅니다. architecture.md에서는 허용 처리, 사람 검토와 복구를, progress.md에서는 현재 DEC-ID, 선택지, 반대 근거, 포기와 재개 조건을 고릅니다. 전체 파일을 보내기보다 해당 결정에 필요한 본문을 먼저 읽고 사용할 범위를 정하세요.

현재 자료만으로 결정한 내용과 아직 묻지 않은 것을 분리합니다. INPUT 식별자가 연습 입력이면 고객 증거로 올리지 않습니다. 내부 고객 자료를 외부에 보낼 수 없다면 허용된 범위로 요약하거나 수동 기록을 유지합니다. 모델이 제안한 판정과 사람이 확정한 실행 범위가 다르면 이유를 progress.md의 새 항목에 남깁니다.

## Q. Markdown과 실제 JSONL은 어떻게 다른가요?

이 키트의 네 Markdown은 사람이 읽고 이유를 이해하기 위한 문서입니다. hplan의 결정과 제외 이력은 JSONL 등록부를 사용합니다. JSONL은 한 줄마다 정해진 구조의 JSON 객체를 저장하며, 도구의 필드와 명령 계약을 따라야 합니다. Markdown의 표를 확장자만 바꿔 넣을 수 없습니다. [공개 README의 결정, 제외 이력 안내](https://github.com/kimsanguine/hplan#readme)에서 현재 구조로 가고, 사용할 버전의 원본과 예제를 읽은 뒤 옮길 항목을 확정하세요.

| 네 문서에서 읽을 내용 | 도구로 이어 쓸 판단 |
|---|---|
| customer.md의 근거와 미확인 | 무엇을 증거로 보고 무엇을 더 확인할지 |
| prd.md의 운영 지속 조건 | 사용량과 비용 입력을 어디까지 확인했는지 |
| progress.md의 포기와 재개 조건 | 이전 제외와 겹칠 때 조건이 달라졌는지 |
| progress.md의 실제 리뷰 | 다음 과제에 재사용할 경험칙의 조건은 무엇인지 |

이 표는 자동 변환 스키마가 아닙니다. hplan의 형식과 네 파일의 정본 역할을 섞지 않고 필요한 값을 검토하는 대응표입니다. 도구를 쓰더라도 고객 약속, 가격, 실제 생성과 게시의 허용은 사람이 확정합니다. 판정이 나왔다는 이유만으로 실행 권한이 늘어나지 않습니다.

## Q. 재사용이 잘됐는지는 무엇으로 보나요?

다음 결정에서 이전의 제외 이유를 찾고, 재개 조건이 지금 충족됐는지 설명해 보세요. 충족되지 않았다면 보류를 유지할 수 있고, 실제 새 근거가 있다면 새 결정을 덧붙일 수 있습니다. 기록이 비어 있을 때는 과거와 충돌하지 않았다는 뜻 이상으로 해석하지 않습니다. 7일의 관찰은 첫 재판단에 쓰고, 장기 고객 효과는 더 긴 주기로 확인합니다.
