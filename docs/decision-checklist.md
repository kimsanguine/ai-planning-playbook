# 한 페이지 결정 점검표

별도 기록 파일을 만들지 않고 자기 progress.md의 `결정` 절을 보며 확인합니다. 빠진 답은 그 절이나 해당 정본 문서에 적습니다. 모르는 값은 확인 담당과 다음 행동을 남깁니다.

| 물을 질문 | 기록할 위치 | 완료 확인 |
|---|---|---|
| 오늘 무엇을 결정하고 누구의 어떤 결과를 바꾸나요? | progress.md의 질문, prd.md의 목표 | 결정 한 건과 사용자 결과를 말할 수 있음 |
| 사업 목표와 시간, 비용, 권한 제약은 무엇인가요? | prd.md의 목표와 운영 지속 조건 | 미확인과 확정 조건을 구별함 |
| 최근의 실제 행동과 현재 대안은 무엇인가요? | customer.md의 사건과 현재 대안 | 출처, 날짜, 가설이 나뉨 |
| 가장 약한 가정과 반대 근거는 무엇인가요? | progress.md의 근거와 반증 | 자료가 없을 때 확인할 행동이 있음 |
| 제거, 표준화, 규칙, AI 중 무엇을 골랐나요? | prd.md의 대안과 범위 | 다른 선택을 하지 않은 이유가 있음 |
| 무엇을 포함하고 의식적으로 포기하나요? | prd.md의 대안과 범위, 포함/제외 필드 | 다시 볼 조건이 progress.md에 있음 |
| 지킬 품질과 중단 조건은 무엇인가요? | prd.md의 품질 기준 | 합격, 실패, 보류와 확인법을 읽을 수 있음 |
| 누가 확정하고 실패하면 어디로 돌아가나요? | architecture.md의 HITL과 복구 | 원본, 권한, 비용의 책임자가 있음 |
| 지금 허용하는 것은 시험인가요, 전체 개발인가요? | progress.md의 허용과 금지 | 실제 행동의 경계가 분명함 |
| owner와 7일 뒤 review 날짜는 누구, 언제인가요? | progress.md의 결정 | 실제 관찰 방법과 다음 선택 조건이 있음 |

## 저장과 재열기

- [ ] 네 파일을 저장하고 닫았다 다시 열었습니다.
- [ ] customer.md의 자료 ID, prd.md의 Q-ID, architecture.md의 참조, progress.md의 DEC-ID로 같은 결정을 따라갔습니다.
- [ ] AI의 설명예와 실제 고객 자료, 예상과 실제 결과를 구별했습니다.
- [ ] 선택 이유, 안 할 일, 다음 행동과 책임자를 설명할 수 있습니다.

## 7일 뒤

새 리뷰 항목에 이전 DEC-ID, 실제 한 일과 못 한 일, 관찰 출처와 기간, 유지, 수정, 축소, 중단/보류, 추가 관찰 중 선택한 것과 이유를 덧붙입니다. 추가 관찰이면 확인 대상, 담당, 날짜와 그동안 보류할 실행 범위를 적습니다. 이전 actual과 이유는 고치지 않습니다. 두 번째 과제에 같은 기준을 적용한 선택은 progress.md의 재사용 기준에 저장하고 다시 엽니다.
