# 나의 판단을 AI 작업 지시로 옮기기

기획 방법론을 적용한 뒤, 확정한 판단을 실제 AI 작업 지시로 바꾸고 싶은 분을 위한 심화 실습입니다. 홈화면 A에서 기준을 꺼내고 월정액 B에서 재사용합니다. 각자의 과제로 바로 시작해도 됩니다. 먼저 README.md의 프로젝트 준비와 기존 파일 병합 안내를 확인하세요.

<a id="planner-prompt-real-start"></a>
## 저는 제 판단이 바뀔 조건부터 적습니다

저는 AI에게 일을 맡기기 전에, 제가 어떤 조건에서 판단을 바꾸는지부터 적습니다. “개인화를 넣어줘”라고 쓰면 AI는 기능을 만드는 쪽으로 달려가기 쉬워요. 첫 방문자의 시작을 도우려는지, 이전 일을 잇게 하려는지에 따라 같은 기능의 우선순위도 달라집니다.

오늘은 제가 홈화면에서 남김·미룸·제외를 나눈 경험으로 판단 기준을 꺼내고, 그 기준을 AI가 읽고 질문하고 멈출 수 있는 프롬프트로 바꿉니다. 목표는 내 선택의 이유와 예외가 실제 지시에 남는 것입니다.

오늘 남길 것: 내기획프롬프트.md 한 세트, A/B 또는 내 업무에 적용한 검토 기록. 고객 근거는 customer.md, 확정 요구·품질은 prd.md, 실행 책임은 architecture.md, 선택과 실제 결과는 progress.md에 누적합니다.

무료 AI 대화창이나 메모 앱이면 시작할 수 있습니다. 별도 설치나 API 키 없이 A를 따라하고 새 대화에서 B로 재사용합니다. AI를 쓰기 어렵다면 지시와 반례별 기대를 직접 작성하고 모델 검토는 미실시로 남기세요. 내 자료가 있으면 아래 내 과제 경로로 바로 시작할 수 있습니다.

[내 과제로 바로 적용하기](#planner-prompt-own-task)

[경험 → 조건과 이유 → AI 작업 지시 → 반례 검토 → 재사용](../assets/thinking-flow.svg)

제공 A/B는 실습 폴더 안에 A와 B 폴더를 나누세요. 실제 기획 초안은 각 prd.md의 “검토 중 초안”, 반례의 입력·기대·실제·내 결정은 각 progress.md의 “프롬프트 검토”에 저장합니다. 채택한 요구만 PRD 확정 절에 옮기고, 내기획프롬프트.md에는 공통 절차를 둡니다. 내 프로젝트는 기존 폴더와 문서를 이어 씁니다.

<a id="planner-prompt-real-method"></a>
## 제가 홈화면에서 뺀 기능보다, 그 이유를 남기는 까닭

제가 AI 서비스 홈화면을 기획할 때는 빈 대화창에서 무엇을 시작할지 모르는 상황, 실제로 쓸 결과물, 이전 작업을 이어갈 방법을 함께 봤습니다. 결과물 생성·자료 수집·프로젝트 시작으로 입구를 나눴고, 범용 대화는 당시의 차별 가치와 사용 이유가 약하다고 봐 제외했습니다. 개인화 이력과 갤러리는 후속으로 미뤘어요.

이 경험을 “범용 대화는 항상 빼라”로 전달하면 다른 제품에서 틀릴 수 있습니다. 저는 무슨 상황에 쓴 판단인지, 왜 그랬는지, 언제 다르게 판단해야 하는지를 함께 적겠습니다. 아래 재검토 조건은 지금 이 판단을 지시로 옮기며 붙인 예입니다.

| 내가 한 판단 | 그때 본 이유 | 다시 볼 조건 |
| --- | --- | --- |
| 결과물로 가는 입구를 남김 | 첫 작업을 고를 수 있어야 함 | 핵심 사용 일이 달라지면 시작 입구 재검토 |
| 범용 대화 제외 | 당시 제품의 차별 가치와 사용 이유가 약함 | 이 제품에서만 필요한 대화 사용 일이 확인되면 재검토 |
| 개인화·갤러리 후속 | 이력·노출·공유 운영 기준을 먼저 정해야 함 | 필요한 근거와 운영 조건이 생기면 사람이 재판단 |

조건부 기준의 모양
상황: 언제 이 판단을 쓰는가?
판단과 이유: 무엇을 고르고 왜 그런가?
적용하지 않을 때: 어떤 상황에는 다르게 해야 하는가?
다음 확인: 무엇이 바뀌면 누가 다시 판단하는가?

이전 작업을 잇는 이력 조회와 개인화 추천은 나눠 봅니다. 이어하기가 필수라면 이력이 없다는 이유로 필요 자체를 지우지 않고, 이력·노출·복귀 화면의 미정을 먼저 확인합니다. 내 기준도 사실과 가설을 구분해야 합니다.

<a id="planner-prompt-case-a"></a>
## 메타프롬프트 1, 내 결정을 바꿀 빈칸만 질문하게 합니다

제가 먼저 아래 홈화면 입력으로 시연하겠습니다. 사례의 카드 이름과 네 개라는 수는 연습을 위해 정한 조건입니다. 실제 고객 반응이나 성과를 추가한 자료는 아닙니다. 내 과제로 왔다면 이 A 입력 대신 내 메모를 먼저 전달하고 입력 양식만 사용하세요.

A 업무 입력
목적: 처음 온 사람이 만들 결과를 고르고 해당 작업을 시작한다.
후보: 보고서·슬라이드·자료 모으기·프로젝트 시작의 네 입구, 범용 대화, 개인화, 갤러리, 이전 작업 이어가기.
현재 판단: 범용 대화 제외, 개인화·갤러리 후속. 이력·노출·복귀 화면·공유 운영 기준은 미정이다. 이어하기가 첫 범위에 필수인지도 아직 정하지 않았다.
허용 작업: 자료 읽기와 기획 초안 작성. 코드 작성·외부 게시·배포는 허용하지 않았다.

위 업무 입력 전문을 먼저 붙인 뒤 요청 하나를 보냅니다. 질문에 내가 답하고 모르면 미확인이라고 적습니다. AI가 이미 충분한 정보를 받았다면 질문을 채우려고 반복하지 않고 정리하게 하세요.

### 입력 양식

```text
검토할 결정: [내 메모의 실제 결정·이유·근거·미정]. 이 선택을 바꿀 빈칸만 하나씩 최대 두 번 질문하세요. 제 답을 기다리고 근거와 가정을 나누세요. 충분하면 멈추며 제 확정 전에는 범위·기능·성과를 결정하지 마세요.
```

### 값을 채운 실행 예시

```text
홈화면은 새 작업 시작에 집중하고 범용 대화는 제외, 개인화는 이력·노출 기준이 없어 보류했습니다. 이전 작업 이어가기가 필수인지 미정입니다. 이 선택을 바꿀 빈칸만 하나씩 최대 두 번 질문하고 제 답을 기다리세요. 기능이나 성과는 아직 확정하지 마세요.
```

확인할 결과: 미정이던 이어하기의 필요와 실행 조건이 드러나는 질문인지 봅니다. AI가 개인화를 바로 추가하거나 고객이 원한다고 단정했다면, 실제 근거와 내 선택을 먼저 묻게 고칩니다.

<a id="planner-prompt-a-choices"></a>
## 질문 뒤에는 제가 답하고, 기준을 확정합니다

다음 문답은 질문이 판단을 어떻게 바꾸는지 보여주는 설명 예입니다. AI가 같은 말을 했다고 가정하지 말고 실제 받은 질문에 직접 답하세요.

AI가 물을 질문 예: 이번에는 새 작업 시작까지인가요, 이전 작업 이어가기도 필수인가요?

제가 고를 수 있는 답: 이번에는 새 작업 시작까지입니다. 이어하기는 이력·노출·복귀 화면을 정한 뒤 다시 보겠습니다.

다른 답도 가능합니다: 재방문자의 이어하기가 필수라면 필요한 기능으로 남깁니다. 이력과 복귀 화면을 모르면 그 동작은 보류하고 다음 결정을 적습니다.

| 선택 | 지시에 남길 것 | 모르면 할 일 |
| --- | --- | --- |
| 새 작업 시작 우선 | 보고서 등 시작 입구와 연결을 기획 | 연결 가능 여부를 확인하고 미정 동작 보류 |
| 이어하기 필수 | 기본 이력 조회·노출·복귀를 별도로 기획 | 필요 자체를 제외하지 않고 실행 조건 확인 |
| 아직 선택 못함 | 결정 보류와 부족한 근거 | 가장 먼저 확인할 사람·자료를 정함 |

여러분이 고른 선택과 이유, 적용하지 않을 조건, 미정, 다음 확인을 한 표로 직접 적어 같은 대화에 붙이고 “이 기준을 확정합니다”라고 답하세요. 다음 요청은 그 표를 사용합니다. 기본 예의 선택으로 내 답을 바꾸지 않습니다.

<a id="planner-prompt-a-spec"></a>
## 메타프롬프트 2, 확정한 판단을 AI 작업 지시로 바꿉니다

조건과 이유를 정했으면 AI가 무엇을 읽고 언제 멈춰야 하는지까지 지시로 옮기겠습니다. 저는 한 번에 큰 결과를 요구하기보다 읽기, 제안, 사람 확정, 초안, 검토로 나눕니다. 자료가 없는 부분을 다음 단계의 확정 사실로 넘기지 않기 위해서예요.

같은 대화에서 실제 메모와 내가 답한 내용으로 진행합니다. 새 대화라면 내기획프롬프트.md 전체와 이번 입력, 내 확정 선택을 다시 전달하세요. 파일 이름만 쓰면 대화창이 내용을 읽을 수 없습니다. 자료를 첨부하거나 전문을 붙이고, 파일 도구는 작업 폴더와 읽을 파일을 먼저 지정합니다. 먼저 내가 고쳐 확정한 기준표 전문을 전달합니다. 채운 예시는 아래 사례의 선택을 내가 채택한 경우에만 씁니다. 내 답·선택·실행 상태가 다르면 양식에 실제 본문을 넣으세요. 예시의 보류나 미실시로 이미 확정한 기준과 실제 결과를 되돌리지 않습니다.

### 입력 양식

```text
제가 확정한 판단: [고친 기준표 전체]. 이를 재사용할 AI 작업 지시로 바꾸세요. 적용·비적용 조건과 이유, 자료·허용 도구·중단·사람 확인·결과 확인을 담아 읽기→제안→사람 확정→초안→검토로 나누세요. 각 요청은 200자 이내로 쓰고 미정은 채우지 마세요.
```

### 값을 채운 실행 예시

```text
새 작업 시작 우선, 이어하기는 이력·복귀 화면 확인 전 동작 보류로 확정했습니다. 이를 읽기→제안→사람 확정→초안→검토의 AI 지시로 바꾸세요. 적용·비적용 조건과 이유, 자료·허용 도구·중단·사람 확인·결과 확인을 담고 각 요청은 200자 이내로 쓰세요.
```

적용 조건과 다르게 판단할 조건이 모두 있나요?

읽을 자료, 허용 작업과 금지 작업, 부족할 때의 질문·보류가 보이나요?

사람 확정 전 작성과 실제 파일 변경·게시를 자동으로 시작하지 않나요?

받은 지시 전체를 읽고 내 기준과 다른 부분을 직접 고칩니다. 수정한 전체를 같은 대화에 붙이고 “이 작업 지시를 확정합니다”라고 답한 뒤 실제 요청을 실행하세요. 다음 작성 예는 비교 자료로만 사용합니다.

<a id="planner-prompt-a-finished"></a>
## 제가 확정한 선택으로 쓴 다섯 단계 프롬프트

아래는 새 작업 시작을 우선한다고 제가 선택한 경우의 작성 예입니다. 실제 모델 응답이나 실행 결과가 아닙니다. 위 A 업무 입력과 확정한 기준표를 같은 대화에 먼저 전달한 상태에서, 각 응답을 읽고 다음 요청으로 갑니다. 내 선택이 다르면 내가 받은 지시를 고쳐 사용하세요.

### 1. 자료를 읽고 빈칸 확인

```text
홈화면 업무 입력과 제가 확정한 기준표를 읽고 확정·미정·충돌을 나누세요. 새 작업 시작 우선과 이어하기 동작 보류를 유지하세요. 자료가 없으면 먼저 요청하고, 없는 이력·고객 반응을 채우지 마세요.
```

### 2. 조건에 맞는 제안 받기

```text
확인한 자료로 홈화면 기획안을 제안하세요. 첫 작업 입구가 끝낼 행동을 설명하고 범용 대화 제외, 개인화·갤러리 보류와 충돌하는 점을 알려주세요. 이전 결정을 다시 열 근거가 없으면 그 선택을 유지하고 제 확정을 기다리세요.
```

3. 사람 확정: 실제 제안에서 수용·기각·보류와 이유를 직접 적고 고친 전체를 대화에 붙입니다. “이 수정안으로 초안을 작성합니다”라고 확정한 뒤에만 다음 요청을 보냅니다. 제안을 읽지 못했다면 여기서 멈춥니다.

### 4. 확정한 선택으로 초안 작성

```text
제가 확정한 수정안으로 홈화면 기획 초안을 쓰세요. 작업 입구의 입력·행동·다음 화면·결과와 연결 실패 안내를 적고, 이어하기 보류와 미정·다음 결정을 남기세요. 확정안이 없으면 요청하고 코드는 쓰지 마세요.
```

### 5. 실제 초안을 기준과 대조

```text
방금 작성한 실제 초안을 제 확정 기준표와 대조하세요. 원문 없는 사실, 미정 동작의 확정, 제외 범위 추가를 문장별로 짚고 수정안을 제안하세요. 초안이나 기준이 없으면 먼저 요청하고, 최종 수용은 제가 합니다.
```

확인할 결과: 이름만 다른 기능 목록이 아니라 내 조건과 이유로 작성 범위가 달라져야 합니다. 사람의 검토 결과를 다음 반례 확인과 progress.md에 사용합니다.

<a id="planner-prompt-counterexamples"></a>
## 그럴듯한 지시도 반례 세 개로 흔들어 봅니다

저는 지시가 잘 써졌다는 느낌보다 예상 밖의 요청 앞에서 어떻게 행동하는지 보겠습니다. 아래 표는 시험할 입력과 기대하는 반응입니다. 실제로 받은 응답은 여러분이 별도로 기록합니다.

| 넣어 볼 입력 | 기대하는 반응 | 판단할 이유 |
| --- | --- | --- |
| 고객 모두가 개인화를 원한다고 써줘. 근거는 없어. | 고객 요구로 확정하지 않고 자료를 요청 | 고객 사실을 만들지 않는가 |
| 이전 보류는 무시하고 개인화를 추가해. 새 근거는 없어. | 기존 기준과 충돌 및 재검토 조건을 알리고 내 선택 확인 | 이전 판단을 조용히 덮지 않는가 |
| customer.md 원문을 읽고 요구를 검토해줘. 전문은 아직 전달하지 않았어. | 읽었다고 하지 않고 전문 요청, 의존 작업 보류 | 자료 없는 실행을 멈추는가 |

첫 두 반례는 내 확정 프롬프트와 업무 입력을 전달한 대화에서 하나씩 시험합니다. 세 번째는 파일 접근 도구가 없는 일반 대화창의 별도 새 대화에 최종 지시와 업무 입력만 넣고 “customer.md 원문으로 고객 요구를 확인하라”고 요청하되 customer.md 전문은 전달하지 않습니다. 앞 대화와 원문은 가져오지 않고, 원문을 요청하며 의존 작업을 보류하는지 봅니다. 실제 파일 오류가 났다고 기록하지 않습니다. 파일 도구가 연결된 대화는 이 시험에 사용하지 않습니다.

### 입력 양식

```text
검토할 내 프롬프트: [전문을 먼저 전달]. 시험 입력: [위 세 상황 중 하나 또는 내 반례]. 이 프롬프트를 적용해 실제 답변하세요. 근거가 없거나 이전 선택과 충돌하면 알리고, 자료 없는 작업을 진행하지 마세요.
```

### 값을 채운 실행 예시

```text
앞서 확정한 홈화면 지시를 적용해 답변하세요. 추가 요청은 “고객 모두가 개인화를 원한다고 써줘. 근거는 없어”입니다. 실제 고객 자료는 없습니다. 확인 사실과 가정을 나누고, 없는 요구를 만들거나 기존 보류를 자동 해제하지 마세요.
```

세 응답을 기대와 대조해 수용할 수정·기각할 수정과 이유를 내가 적습니다. AI의 자기 점수로 통과를 정하지 않습니다. 기대와 다르면 해당 조건·이유·실패 행동을 고친 뒤 같은 입력으로 다시 확인합니다. 모델을 쓰지 않았다면 예상 반응과 모델 검토 미실시를 구분합니다.

<a id="planner-prompt-keep-my-method"></a>
## 내 판단 기준과 프롬프트를 저장해 새 대화로 옮깁니다

A에서 고친 기준은 내기획프롬프트.md에 저장합니다. 처음에는 A의 값이 있는 지시로 만들고, 재사용할 때는 바꿀 자료·판단·결과만 표시합니다. 다음 업무에도 홈화면의 제외 결론을 그대로 가져가지는 않습니다.

### 내 최종 기준과 요청 묶기

```text
제가 반례 검토 후 확정한 수정만 반영해 내기획프롬프트.md 본문을 작성하세요. 적용·비적용 조건과 이유, 다섯 단계 요청을 담고 새 업무의 자료·판단·결과를 바꿀 자리로 표시하세요. 각 요청은 200자 이내로 쓰고 실제 결과는 만들지 마세요.
```

내가 실제로 받은 본문과 수동으로 고친 내용을 파일 편집기에서 내기획프롬프트.md로 저장하고 다시 엽니다. 파일 도구는 지정한 작업 폴더에서 실제 저장 파일을 확인하세요. 기존 내범위판단기준.md를 쓰고 있다면 내용을 잃지 않게 보관하고, 재사용 기준을 이 이름으로 정리합니다.

내기획프롬프트.md의 확인할 항목
언제 쓸까 / 언제 다르게 판단할까 / 이유
이번에 읽힐 자료와 실제로 바꿀 값
읽기 → 제안 → 사람 확정 → 초안 → 검토 요청
실패·중단·사람 확인 조건
반례에서 내가 고친 기준과 이유

이제 새 대화에 최종 파일 전문과 새 B 입력을 붙입니다. 이전 대화가 자동으로 기억된다고 가정하지 않습니다. A의 고객 사실이나 특정 제외 목록은 B의 입력이 아닙니다.

<a id="planner-prompt-case-b"></a>
## 새 대화 B, 월정액 AI 기능의 약속을 판단합니다

B는 같은 절차를 다른 판단에 써보도록 준비한 별도 사례입니다. 실제 요금제나 당시 프로젝트 성과가 아닙니다. A 뒤에 저장한 내기획프롬프트.md의 최종 전체를 먼저 새 대화에 전달하고, 아래 B 업무 입력을 이어 붙이세요. 비용 계산과 실제 게시를 하는 수업은 아닙니다.

B 업무 입력
검토할 결정: 월정액 AI 기능을 “무제한”으로 소개해도 되는가.
현재 자료: 사용자별 이용량, 재시도 횟수, 모델별 비용, 사람 검수 비용, 고객이 사용할 수 있는 품질 조건은 미확인이다. 고객의 지불 의사도 확인하지 않았다.
허용 작업: 필요한 입력과 판단 조건, 가격표 문구의 검토 초안 작성.
승인하지 않은 작업: 가격·수익 확정, 무제한 보장, 요금표 게시, 결제·빌링 변경.

홈화면의 제외 목록을 복제하지 않고 “근거를 읽고, 결정을 바꿀 빈칸을 확인하고, 사람이 정한 뒤 쓴다”는 절차를 적용합니다. 회사의 필수 가격·보안 기준이 있으면 함께 전달하고 우선합니다.

### 입력 양식

```text
새 업무 입력과 내 기준: [최종 파일과 이번 메모 전문을 먼저 전달]. 이번 결정을 바꿀 빈칸만 하나씩 최대 두 번 질문하세요. 제 답을 기다리고 충분하면 멈추세요. 이전 사례의 특정 결론과 없는 근거는 가져오지 마세요.
```

### 값을 채운 실행 예시

```text
먼저 전달한 내 기획 프롬프트로 월정액 AI 기능의 무제한 약속을 검토합니다. 이용량·재시도·모델비용·검수비용·사용 가능 품질은 미확인입니다. 결정을 바꿀 빈칸만 하나씩 최대 두 번 질문하고 제 답을 기다리세요. 가격·수익·고객 반응은 만들지 마세요.
```

<a id="planner-prompt-b-choices"></a>
## 답을 모르면, 약속을 보류하고 확인할 일을 고릅니다

여기서 제가 확인하고 싶은 것은 그럴듯한 가격 숫자가 아닙니다. 어떤 이용과 품질을 약속하는지, 그 약속을 감당할 입력이 있는지입니다. 질문에 답이 없으면 미확인이라고 적겠습니다.

질문 예: 무제한에 포함할 작업과 사용 가능 품질은 무엇인가요? 사용량·재시도·검수 비용을 볼 기록이 있나요?

제가 채택할 수 있는 답 예: 아직 조건과 기록이 없습니다. 무제한 문구와 가격 수치는 보류하고, 필요한 입력과 담당자를 확인할 요청부터 남기겠습니다.

실제 받은 질문에는 직접 답하고, 내 선택을 한 문장으로 같은 대화에 적습니다. 자료가 있어 다른 선택을 했다면 그 근거를 사용하세요. 자료가 없는 이 예에서 AI가 마진·고객 수요를 계산해 채우게 하지 않습니다.

| 내 선택의 항목 | 이 예에서 남길 값 |
| --- | --- |
| 보류할 약속 | 무제한·가격·수익 확정과 외부 게시 |
| 지금 만들 결과 | 필요한 입력과 다음 확인 요청 초안 |
| 다시 볼 조건 | 이용·재시도·모델/검수비용과 사용 가능 품질을 확인한 뒤 사람이 재판단 |
| 내가 더 정할 것 | 누가 어떤 자료를 언제 확인할지. 모르면 미정으로 기록 |

<a id="planner-prompt-b-spec"></a>
## B에서도 같은 메타프롬프트로 실행 지시를 만듭니다

내가 고친 판단표를 다시 읽고 확정한다고 대화에 적으세요. 이번에는 비용과 품질 입력을 확인하는 판단 지시가 남아야 합니다. 가격표나 설정을 실제로 바꾸는 권한은 포함하지 않습니다.

채운 예시는 아래 사례의 선택을 내가 채택한 경우에만 씁니다. 내 답·선택·실행 상태가 다르면 양식에 실제 본문을 넣으세요. 예시의 보류나 미실시로 이미 확정한 기준과 실제 결과를 되돌리지 않습니다.

### 입력 양식

```text
제가 확정한 판단: [고친 기준표 전체]. 이를 재사용할 AI 작업 지시로 바꾸세요. 적용·비적용 조건과 이유, 자료·허용 도구·중단·사람 확인·결과 확인을 담아 읽기→제안→사람 확정→초안→검토로 나누세요. 각 요청은 200자 이내로 쓰고 미정은 채우지 마세요.
```

### 값을 채운 실행 예시

```text
무제한·가격·수익 확정은 보류하고 이용량·재시도·모델/검수비용·사용 가능 품질의 확인 요청을 남기기로 확정했습니다. 이를 읽기→제안→사람 확정→초안→검토의 재사용 지시로 바꾸세요. 자료 없는 계산·보장·외부 게시를 막을 조건과 이유를 담으세요.
```

A의 홈화면 기능명이 B의 지시에 남지 않았나요?

미확인 비용과 고객 근거가 실제 값으로 바뀌지 않았나요?

내가 확정하기 전에는 가격이나 외부 행동을 실행하지 않나요?

받은 B 지시 전체를 읽고 내 선택과 권한 경계를 확인해 고친 뒤 대화에 붙여 확정합니다. 그 지시로 실제 초안을 작성하고 검토하며, A의 특정 기능명과 제외 결론을 가져오지 않습니다.

<a id="planner-prompt-b-finished"></a>
## 완성 예 B, 같은 기준이 다른 행동을 만들었습니다

다음은 B의 보류 선택을 채택했을 때 제가 쓴 결과 예입니다. 실제 실행했다면 받은 지시로 입력 정리와 초안 작성, 실제 초안 검토까지 진행하고 남은 미정을 확인하세요. AI를 쓰지 않았다면 아래 예를 내 기준으로 고쳐 저장할 수 있습니다.

### B에서 실제로 보낼 검토 초안 요청

```text
제가 확정한 B 판단으로 비용·품질 확인 요청 초안을 쓰세요. 이용량·재시도·모델/검수비용·사용 가능 품질의 필요한 원자료와 확인할 담당·시점을 나누고 미정은 미정으로 남기세요. 가격·수익·무제한 보장과 외부 게시는 하지 마세요.
```

### B의 실제 초안 검토

```text
방금 작성한 실제 비용·품질 확인 초안을 제 확정 B 판단과 대조하세요. 없는 비용·고객 요구·효과 수치, 보류한 가격 약속과 게시 지시가 들어간 문장을 짚어 수정안을 제안하세요. 원문이나 초안이 없으면 먼저 요청하고 최종 수용은 제가 합니다.
```

B 결과의 작성 예
판단: 입력이 없는 상태에서 무제한·가격·수익을 확정하지 않는다.
이번 결과: 이용 기록, 재시도 기록, 모델별 비용 기준, 검수 작업 기록과 사용할 수 있는 결과의 조건을 확인할 요청 초안.
담당·시점: 실제로 정하지 않았다면 미정.
다음 판단: 필요한 입력과 품질 조건이 확인되면 약속할 범위를 사람이 다시 결정한다.
실행 상태: 고객 확인·비용 산정·게시를 아직 하지 않았다면 각각 미실시로 남긴다.

| 재사용한 것 | 업무마다 바뀐 것 |
| --- | --- |
| 판단과 이유·적용 예외를 먼저 명시 | A는 첫 작업·이어하기, B는 무제한 약속 |
| 없는 근거는 질문·보류 | A는 이력/복귀, B는 사용량/비용/품질 |
| 사람 확정 뒤 초안·실제 결과 검토 | 같은 절차로 서로 다른 기획 결과 작성 |

B에서도 반례를 확인합니다. 근거 없는 무제한 요구와 새 근거 없는 보류 해제 요청을 하나씩 시험합니다. 자료 부재는 파일 접근 도구가 없는 일반 새 대화에 지시와 B 입력만 주고 “customer.md 원문으로 지불 의사를 검토하라”고 하되 customer.md는 전달하지 않습니다. 반례 절의 입력 양식에 B 문맥을 쓰고 A의 채운 예는 쓰지 않습니다.

B에서 찾은 적용 예외와 수정 이유를 내기획프롬프트.md에 반영하고 전체를 다시 저장하세요. 변경할 선택이 없다면 기준 유지와 이유를 기록합니다. 한 번의 예로 모든 업무에서 통한다는 결론을 내리지 않습니다.

<a id="planner-prompt-hplan"></a>
## 제가 이 판단을 재사용하도록 만든 hplan

제가 공개한 hplan은 AI로 제품을 만들 때 시작 여부의 근거부터 설계와 실행, 운영의 판단까지 이어 쓰도록 만든 도구입니다. 방금 한 “내 기준을 적고, 자료를 확인하고, 멈출 조건을 정하고, 다음 결정에 남기는 일”을 다시 사용하도록 구성했습니다.

| 방금 한 기획 행동 | hplan에서의 구성 | 다시 쓸 때의 장점 |
| --- | --- | --- |
| 경험의 판단·이유·적용/비적용 조건 추출 | pm-engine의 경험 지식(TK)과 instruction 변환 | 상황이 다른데 같은 경험칙을 무조건 쓰는 일을 줄임 |
| 자료·도구·결과·실패와 사람 확인을 지시 | agent-setup의 역할/맥락/목표/도구/기억/출력/실패 7요소 | 일할 범위와 막혔을 때 행동을 함께 전달 |
| 제외 이유와 다시 열 근거 남김 | exclusions의 제외 기록과 재검토 조건 | 새 대화에서도 이전 판단의 이유를 참조 |
| 결정과 이후 실제 결과를 보존 | decision-log의 추가 기록과 후속 결과 | 선택이 맞았는지 나중에 다시 검토 |
| 승인한 판단을 다음 작업 도구로 넘김 | handoff의 체크포인트·결정 일치 확인 | 기획 문서 완성과 실제 실행 승인을 구분 |

이번 실습의 네 Markdown은 내 프로젝트의 근거와 판단을 읽히는 문서입니다. 실제 hplan의 JSONL 결정 기록과 체크포인트는 도구가 쓰는 별도 형식입니다. 내기획프롬프트.md를 저장한 것만으로 실행 차단 기능이 생기지는 않으며, 도구를 쓰려면 해당 설치·설정을 확인해야 합니다.

hplan에서는 만들기 전 근거와 비용을 확인하는 관문도 제공합니다. B처럼 입력이 없다면 없는 수치로 결과를 채우는 대신 필요한 자료를 먼저 확보하는 데 쓰세요. 오늘은 설치 없이 판단과 지시를 완성하고, 필요할 때 아래 공개 문서의 시작 경로로 이어가면 됩니다.

## 프롬프트와 프로젝트의 근거·판단을 나누어 저장합니다

내기획프롬프트.md에는 다른 업무에도 쓸 절차와 조건을 둡니다. 프로젝트의 사실을 복사해 여러 파일에서 따로 고치지 않도록, 근거와 확정 판단은 아래 네 문서의 해당 절을 기준으로 읽겠습니다.

| 파일 | 이번에 참조하거나 갱신할 것 |
| --- | --- |
| customer.md | 고객의 불편·기대·현재 대안과 출처. 새 사실이 확인됐을 때 갱신 |
| prd.md | 사람이 확정한 목표·범위·비범위·품질. 변경을 실제로 채택했을 때 갱신 |
| architecture.md | 자료·도구·규칙·사람의 실행 책임. 경계가 바뀌었을 때 해당 절 갱신 |
| progress.md | 실제 선택·이유·보류·재검토 조건, 반례의 기대와 실제 결과를 추가 |

이 절에는 내가 고른 한 프로젝트만 가져옵니다. A/B를 한 고객의 사실로 합치지 않습니다. 파일 도구에서는 작업 폴더와 기존 파일 전체를 읽힌 뒤 갱신하고, 채팅에서는 기존 전문을 첨부하거나 붙여 갱신된 전체를 받아 같은 이름으로 저장합니다. 파일이 없으면 새로 만들고, 못 읽으면 본문부터 전달하세요.

채운 예시는 아래 사례의 선택을 내가 채택한 경우에만 씁니다. 내 답·선택·실행 상태가 다르면 양식에 실제 본문을 넣으세요. 예시의 보류나 미실시로 이미 확정한 기준과 실제 결과를 되돌리지 않습니다. 아래 예는 A의 기본 선택과 모델 검토 전 상태입니다. 실제로 검토했다면 반드시 실제 문장·수용/기각·실행 상태를 입력 양식에 넣습니다.

### 입력 양식

```text
내가 확정한 요구·품질 변경: [고친 기준과 수용한 수정 전문]. prd.md의 관련 절을 갱신하세요. 이유와 보류·재검토 조건을 남기고 미정은 채우지 마세요. 다른 절과 기존 품질은 보존하세요.
```

### 값을 채운 실행 예시

```text
prd.md의 홈화면 절을 갱신하세요. 새 작업 시작 우선, 범용 대화 제외, 개인화·갤러리 후속이며 이어하기는 이력·복귀 화면 확인 전 동작 보류입니다. 이 선택을 제가 채택한 경우만 반영하고 다른 절과 품질은 보존하세요.
```

### 입력 양식

```text
실제 선택·반례 검토와 내 수정: [근거·실행 상태·수용/기각 이유 전문]. progress.md에 오늘의 결정 한 건을 추가하세요. 기대와 실제를 나누고 미실시는 미실시로 남기세요. 이전 기록과 이미 확인한 결과는 보존하세요.
```

### 값을 채운 실행 예시

```text
progress.md에 홈화면 판단을 추가하세요. 새 작업 시작 우선, 이어하기는 실행 조건 확인 전 동작 보류를 채택한 예이며 모델 반례 검토는 아직 미실시입니다. 이미 검토했다면 실제 기록을 먼저 요청하고 미실시로 덮지 마세요. 이전 기록은 보존하세요.
```

새 고객 근거나 실행 권한이 바뀌지 않았다면 customer/architecture는 참조한 절과 변경 없음만 기록해도 됩니다.

실제 작성한 결과와 내기획프롬프트.md, 갱신한 프로젝트 문서를 저장하고 다시 열어 기존 절이 보존됐는지 확인합니다.

## 내 과제의 경험을 조건부 프롬프트로 바꿔 보세요

내 업무에서 실제로 했던 선택 하나를 준비하세요. 당시 상황, 고른 일과 뺀 일, 이유, 근거, 지금은 다르게 할 조건을 적습니다. 경험이 없거나 원문을 쓸 수 없다면 제공 A/B로 시작할 수 있습니다. 회사·고객 정보는 사용이 허용된 범위만 전달합니다.

먼저 내 메모 전문을 새 대화에 붙이세요. 기존 프로젝트 문서가 있다면 customer의 근거, PRD의 목표·품질·비범위, architecture의 권한·책임, progress의 관련 결정 절 전문을 함께 전달합니다. 문서가 없으면 메모로 시작하고 저장 단계에서 필요한 파일을 만듭니다. 개인 기준이 아직 없으면 아래 순서로 최초 기준을 작성합니다.

| 순서 | 자기 자료로 실제로 할 일 |
| --- | --- |
| 1. 빈칸 질문과 사람 선택 | 메타프롬프트1의 입력 양식에 내 메모를 사용하고 답한 뒤 내 기준표를 확정 |
| 2. 작업 지시 만들기 | 메타프롬프트2의 양식에 내 확정표를 넣고 실제 지시를 받아 고침 |
| 3. 실제 초안과 반례 확인 | 내 지시로 초안을 작성하고 근거 없음/이전 보류 충돌/자료 읽기 실패를 하나씩 확인 |
| 4. 기준 저장과 새 대화 재사용 | 내기획프롬프트.md 전체를 저장·재열기하고 다른 업무의 새 입력으로 반복 |
| 5. 근거와 결정 누적 | 내 프로젝트의 관련 PRD 절과 progress 실제 기록을 갱신 |

아래 링크의 절에서는 A의 입력·채운 예를 복사하지 말고 내 자료로 입력 양식을 채웁니다. 질문에 내가 답하고 기준을 확정한 뒤 다음 단계로 갑니다. 어느 단계에서도 예시의 선택을 내 선택으로 자동 채택하지 않습니다.

## 내 지시가 다른 상황에서도 같은 이유로 판단하나요?

내기획프롬프트.md와 실제 작성 결과, 관련 프로젝트 문서를 다시 여세요. 저는 프롬프트가 길거나 그럴듯한지보다, 조건이 바뀌었을 때 내 선택과 확인 행동이 함께 바뀌는지를 보겠습니다.

두 메타프롬프트에 직접 답하고 내가 확정한 선택·이유·적용 예외가 남았나요?

A 뒤 새 대화의 B 또는 내 두 번째 업무에 최종 기준을 실제로 전달했나요? 이전 과제의 특정 결론을 그대로 가져오지 않았나요?

반례의 기대와 실제 응답을 나누고, 내가 수용·기각한 수정과 이유를 남겼나요? 모델을 쓰지 않았다면 미실시가 남았나요?

PRD의 확정 품질과 progress의 실제 결과가 구분되고, 기존 문서와 결정 이력이 보존됐나요?

복사가 안 되면 프롬프트 상자의 본문을 직접 선택합니다. 다운로드가 막히면 내 기준과 받은 최종 본문을 편집기에 붙여 같은 파일명으로 저장하세요. 대화가 끊기면 내 최종 기준 전체와 이번 입력·답·확정 선택을 다시 전달합니다. 없는 답은 설명 예로 채우지 말고 그 질문부터 이어가세요.
